## workflows/ 独立工作流层详细解析

`workflows/` 目录包含两个独立的、面向特定任务的工作流定义文件，它们不是主流水线的一部分，而是**辅助流程**：

- `create-template.md`：创建新的全局布局模板（供 `templates/layouts/` 库使用）
- `topic-research.md`：当用户只提供主题名称或简短描述时，从零开始搜集内容并生成结构化的 Markdown 文档和图片素材

这些文件是**给 AI 阅读的指令**，AI 在执行时需要严格按照其中的步骤、门禁和角色定义来操作。下面分别详细解析，并提供完整的使用指南和示例。

---

# 一、`create-template.md` —— 创建全局布局模板

### 文件解析

#### 元数据
```yaml
description: Generate a new PPT layout template based on existing project files or reference templates
```
- 说明该工作流的用途：基于现有项目文件或参考模板生成新的 PPT 布局模板。

#### 角色调用
> **Role invoked**: [Template_Designer](../references/template-designer.md)

执行该工作流时，AI 将切换到 **Template_Designer** 角色（定义见 `references/template-designer.md`），负责生成模板文件。

#### 目标
生成一套完整的、可复用的 PPT 布局模板，用于**全局模板库**（`templates/layouts/`），而非项目级的一次性定制。输出必须能被 `layouts_index.json` 发现。

#### 流程概览
```
Gather Brief -> Create Directory -> Invoke Template_Designer -> Validate Assets -> Register Index -> Output
```

### Step 1: 收集模板信息（必填项）

AI 需要向用户确认以下信息：

| 项 | 必填 | 说明 |
|----|------|------|
| 新模板 ID | ✅ | 目录名/索引键，建议 ASCII 字符（如 `my_company`）；若使用中文品牌名，必须文件系统安全且与 `layouts_index.json` 精确匹配 |
| 模板显示名称 | ✅ | 人类可读的名称 |
| 分类 | ✅ | 必须为 `brand` / `general` / `scenario` / `government` / `special` 之一 |
| 适用场景 | ✅ | 典型用途，如 “年报/答辩/政府简报” |
| 调性摘要 | ✅ | 简短描述，如 “现代、克制、数据驱动” |
| 主题模式 | ✅ | 推荐时的主题描述，如 “浅色主题（白底 + 蓝色点缀）” |
| 画布格式 | ✅ | 默认为 `ppt169`；如果需要其他格式，必须在生成前明确指定 |
| 参考源 | ❌ | 现有项目、截图文件夹或 `.pptx` 模板文件路径 |
| 主题色 | ❌ | 主色 HEX 值（可从参考源自动提取） |
| 设计风格 | ❌ | 额外的风格说明、装饰语言、品牌提示 |
| 资产列表 | ❌ | 模板包中包含的 logo、背景纹理、参考图片 |
| 快速查找标签 | ❌ | `layouts_index.json` 中 `quickLookup` 使用的标签，如 `technology`, `finance`, `academic` |

**如果提供了参考源（尤其是 `.pptx` 文件）**，必须先运行轻量级导入工具提取资产和样式元数据：
```bash
python3 skills/ppt-master/scripts/pptx_template_import.py "<reference_template.pptx>"
```
该工具会生成 `manifest.json`, `analysis.md`, `assets/` 目录。AI 在生成模板时应以这些提取的数据为准（如主题颜色、字体、可重用背景），而不是直接转换 PPTX 形状。

**重要原则**：
- 导入的 PPTX 是**参考源**，不是直接转换目标。目标是重建一个干净的、符合 PPT Master 规范的模板包，而不是 1:1 翻译所有形状。

### Step 2: 创建模板目录
```bash
mkdir -p "skills/ppt-master/templates/layouts/<template_id>"
```
- 输出位置必须是全局模板目录（`skills/ppt-master/templates/layouts/`），不能放在项目目录。
- 目录名必须与最终的模板 ID 一致。

### Step 3: 调用 Template_Designer 角色
AI 切换到 `Template_Designer` 角色，依据收集到的信息（和可选的导入输出）生成：
- `design_spec.md`：完整的设计规范文档
- 4 个核心模板：`01_cover.svg`, `02_chapter.svg`, `03_content.svg`, `04_ending.svg`
- 可选：`02_toc.svg`（目录页）
- 可选：模板资产（logo、PNG、JPG、参考 SVG）

**新模板占位符契约（强制）**：

| 页面类型 | 占位符 |
|----------|--------|
| 封面 | `{{TITLE}}`, `{{SUBTITLE}}`, `{{DATE}}`, `{{AUTHOR}}` |
| 章节页 | `{{CHAPTER_NUM}}`, `{{CHAPTER_TITLE}}` |
| 内容页 | `{{PAGE_TITLE}}`, `{{CONTENT_AREA}}`, `{{PAGE_NUM}}` |
| 结尾页 | `{{THANK_YOU}}`, `{{CONTACT_INFO}}` |
| 目录页 | 使用索引占位符：`{{TOC_ITEM_1_TITLE}}`, `{{TOC_ITEM_1_DESC}}` 等 |

**禁止**为新模板引入一次性占位符家族（如 `{{CHAPTER_01_TITLE}}`）。如果确实需要扩展占位符，必须在 `design_spec.md` 中明确定义并保持命名一致。

### Step 4: 验证模板资产
- 列出文件：`ls -la skills/ppt-master/templates/layouts/<template_id>`
- 运行 SVG 质量检查：
  ```bash
  python3 skills/ppt-master/scripts/svg_quality_checker.py "skills/ppt-master/templates/layouts/<template_id>" --format <canvas_format>
  ```
- **检查清单**：
  - [ ] `design_spec.md` 包含完整的设计规范
  - [ ] 4 个核心模板都存在
  - [ ] 如果包含目录页，占位符使用规范的索引形式
  - [ ] SVG viewBox 与选择的画布格式匹配（`ppt169` 为 `0 0 1280 720`）
  - [ ] 占位符名称符合新模板契约且在 `design_spec.md` 中一致
  - [ ] 模板中引用的资产文件实际存在

**此步骤是硬门禁**。验证不通过不能注册到索引。

### Step 5: 注册模板到库索引
更新 `skills/ppt-master/templates/layouts/layouts_index.json`：
- 增加 `meta.total`
- 更新 `meta.updated` 为当前日期
- 在相应的 `categories.<category>.layouts` 数组中添加模板 ID
- 在 `quickLookup` 中添加适当的关键词映射
- 添加 `layouts.<template_id>` 元数据块

`layouts_index.json` 是模板发现的**唯一真实来源**。未注册的模板目录视为不完整。

如果人类可读的 `templates/layouts/README.md` 摘要表需要同步，应在更新 JSON 索引后手动更新（JSON 索引优先）。

### Step 6: 输出确认
输出格式见原文件。

## 如何使用 `create-template` 工作流：完整指南

### 适用场景
- 你想为某个品牌、客户或特定使用场景创建一套可复用的 PPT 布局模板。
- 你有一个现有的 PPTX 模板文件，希望转换为 PPT Master 的全局模板格式。
- 你想为社区贡献一套新模板。

### 准备工作

#### 1. 确定模板基本信息
- **模板 ID**（英文小写+下划线，如 `mybank_annual`）
- **模板显示名称**（如 “MyBank Annual Report Template”）
- **分类**（`brand`/`general`/`scenario`/`government`/`special`）
- **适用场景**（如 “年度报告、董事会演示”）
- **调性摘要**（如 “专业、权威、数据驱动”）
- **主题模式**（如 “浅色主题，白底 + 品牌深蓝色点缀”）
- **画布格式**（通常 `ppt169`）
- **快速查找标签**（可选，如 `finance`, `corporate`）

#### 2. 准备参考素材（可选但推荐）
- **PPTX 模板文件**：放置于任意目录，例如 `~/Desktop/my_template.pptx`
- **截图或设计稿**：可帮助 AI 理解布局。
- **品牌资产**：logo 图片（PNG/JPG）、背景纹理、品牌色板。

### 完整操作步骤（与 AI 对话）

假设你要为 “MyBank” 创建一个年度报告模板。

**步骤 1：启动工作流**
```
你：请使用 create-template 工作流，为 MyBank 创建一个年度报告模板。
```

**步骤 2：AI 收集信息**
AI 会询问：
- 模板 ID（建议 `mybank_annual`）
- 显示名称
- 分类（品牌风格）
- 适用场景（年度报告、董事会演示）
- 调性（专业、权威、数据驱动）
- 主题模式（浅色主题，白底 + 深蓝色点缀）
- 画布格式（默认 ppt169）
- 是否有参考 PPTX 文件？

**步骤 3：提供参考文件**
```
你：我有一个现成的 PPTX 模板文件，放在 ~/Desktop/MyBank_Template.pptx。
```

**步骤 4：AI 运行导入工具**
AI 会自动执行：
```bash
python3 skills/ppt-master/scripts/pptx_template_import.py ~/Desktop/MyBank_Template.pptx
```
导入结果输出到 `MyBank_Template_template_import/` 目录，包含 `manifest.json`, `analysis.md`, `assets/`。

**步骤 5：AI 生成模板**
AI 切换到 Template_Designer 角色，根据导入的元数据和你的要求，生成：
- `design_spec.md`（包含品牌色 `#003366`, 字体 `system-ui`, 页眉高度等）
- `01_cover.svg`（使用 `{{TITLE}}`, `{{SUBTITLE}}`, `{{DATE}}`, `{{AUTHOR}}`）
- `02_chapter.svg`（使用 `{{CHAPTER_NUM}}`, `{{CHAPTER_TITLE}}`）
- `03_content.svg`（页眉 + 页脚 + `{{CONTENT_AREA}}`）
- `04_ending.svg`（`{{THANK_YOU}}`, `{{CONTACT_INFO}}`）
- 可选 `02_toc.svg`（使用 `{{TOC_ITEM_1_TITLE}}` 等）
- 将资产（如 logo）复制到模板目录，并在 SVG 中引用。

**步骤 6：AI 验证模板**
运行 `svg_quality_checker.py` 检查，并手动验证文件存在性。

**步骤 7：AI 注册索引**
更新 `layouts_index.json`：
- `meta.total` +1
- `categories.brand.layouts` 添加 `"mybank_annual"`
- `quickLookup` 添加 `"finance": ["mybank_annual"]`（如果已有则追加）
- 添加 `layouts.mybank_annual` 元数据块

**步骤 8：输出确认**
AI 返回类似原文件中的确认表格。

### 注意事项

- **模板目录必须放在 `skills/ppt-master/templates/layouts/`**，不能放在项目目录。
- **占位符必须严格遵循新模板契约**，不要使用旧式或自定义占位符。
- **SVG 必须通过质量检查**，否则不能注册。
- **索引文件是 JSON**，注意逗号、括号等语法，避免损坏。
- **如果参考源是 PPTX**，导入工具提取的只是粗略元数据，你可能需要手动微调 SVG（如调整元素位置、替换占位符）。AI 会尽力重建，但复杂动画或特殊效果无法保留。
- **资产文件（logo 等）** 应放在模板目录下，并在 SVG 中使用相对路径引用（如 `href="logo.png"`）。后处理时它们会被复制到项目的 `images/` 目录。

# 二、`topic-research.md` —— 主题研究（内容搜集）

### 文件解析

#### 元数据
```yaml
description: Research a topic from scratch when the user provides only a brief description or requirements without detailed source materials. Produces a structured Markdown document and a folder of related images.
```
- 说明：当用户只提供主题名称或简短描述，没有详细源材料时，从零开始研究主题，生成结构化的 Markdown 文档和相关图片文件夹。

#### 触发条件
用户只提供了主题名称、简短描述或一组需求 —— **没有** PDF、DOCX、URL 或其他源文件。

示例：
- “制作一个关于久石让的 PPT”
- “创建关于可再生能源趋势的演示文稿”
- “我想介绍我们的新产品（附简短描述）”

#### 交付物
所有输出**必须**放在 `projects/` 目录下：

| 交付物 | 路径 | 示例 |
|--------|------|------|
| 结构化 Markdown 文档 | `projects/<topic_name>.md` | `projects/joe_hisaishi.md` |
| 图片文件夹 | `projects/<topic_name>/`（与文档同名，无扩展名） | `projects/joe_hisaishi/` |

> **命名一致性**：Markdown 文件名（不含 `.md`）和图片文件夹名**必须完全相同**。
> **输出目录规则**：文档和图片文件夹**必须**创建在 `projects/` 内，绝不能放在仓库根目录或其他位置。

#### 流程概览
```
Confirm Topic → Research Content → Collect Images → Output
```

### Step 1: 主题确认（阻塞点）

⛔ **阻塞**：在开始研究前，确认以下信息。如果用户初始消息已明确覆盖，则跳过确认直接继续。

| 项 | 说明 | 示例 |
|----|------|------|
| **主题** | 核心主题 | 久石让 |
| **范围/重点** | 要涵盖哪些方面 | 生平、主要作品、与宫崎骏的合作、获奖情况 |
| **深度** | 表面概述 vs. 深入探讨 | 一般知识水平 |
| **语言** | 输出语言 | 中文 |

> 如果用户请求已经足够清晰（如 “制作关于久石让的 PPT”），推断合理的默认值并直接继续 —— 不要过度询问。

### Step 2: 内容研究

#### 2.1 信息收集
使用 `WebSearch` 和 `WebFetch` 从多个来源收集信息。优先级：
- **高**：维基百科/百科全书 → 权威概述、时间线、关键事实
- **高**：官方网站 → 一手信息
- **中**：新闻/媒体文章 → 近期事件、奖项、公众反响
- **低**：专业数据库 → 行业特定数据（如相关）

**研究策略**：
1. 从广泛的 WebSearch 开始，了解主题全貌。
2. WebFetch 2-3 个关键权威页面（维基百科、官网）获取详细内容。
3. 根据需要补充特定子主题的定向搜索。

#### 2.2 内容组织
将收集的信息组织成结构化的 Markdown 文档，骨架如下（可根据主题调整）：

```markdown
# <Topic Name>

> 一行简短描述。

## 概述
[2-3 段总结]

## 背景 / 历史
[时间线、起源故事、关键里程碑]

## 关键方面
### 方面 1: [...]
### 方面 2: [...]
### 方面 3: [...]

## 成就 / 影响
[奖项、认可、影响]

## 关键事实与数据
| 项目 | 值 |
|------|-----|
| ... | ... |

## 来源
- [来源 1 标题](URL)
- [来源 2 标题](URL)
```

**内容指南**：
- 包含具体事实、日期和名称 —— 避免模糊概括。
- 保留关键引述。
- 注明数据来源以确保可验证性。
- 追求 PPT 就绪的内容密度：足以填充 10-15 页幻灯片，但不是详尽的研究论文。

#### 2.3 保存文档
保存到 `projects/` 目录：`projects/<topic_name>.md`

### Step 3: 图片收集

#### 3.1 图片来源策略
按优先级搜索**公开可用、可自由使用**的图片：

| 来源 | 如何找到 | 许可说明 |
|------|----------|----------|
| **维基百科/维基共享资源** | WebFetch 维基页面 → 提取 `upload.wikimedia.org` 图片 URL → 获取完整分辨率版本（移除 `/thumb/` 和尺寸后缀） | CC-BY-SA 或公共领域 |
| **官方网站** | WebFetch 官方页面 → 查找图库或新闻稿部分 | 通常允许编辑/教育使用 |
| **政府/机构发布** | WebSearch 官方新闻包、公共图库 | 通常公共领域 |
| **知识共享搜索** | WebSearch 使用 `site:commons.wikimedia.org` 或 `site:flickr.com/photos` + creative commons | 检查具体 CC 许可 |

**避免**：带水印的图库网站、受版权保护的商业图片、无明确许可的社交媒体上传。

#### 3.2 图片选择标准

| 标准 | 指南 |
|------|------|
| **数量** | 6-12 张（足够支持 10-15 页 PPT） |
| **多样性** | 混合肖像、场景、logo、活动照片（视主题而定） |
| **分辨率** | 优先 1000px+ 宽度；避免缩略图 |
| **相关性** | 每张图片应有明确用途（封面、插图、背景） |
| **宽高比混合** | 包含横版（用于背景）和竖版（用于人物肖像） |

#### 3.3 下载过程
```bash
# 在 projects/ 下创建图片文件夹（与文档同名）
mkdir -p "projects/<topic_name>"

# 用描述性文件名下载图片
curl -L -o "projects/<topic_name>/descriptive_name.jpg" "<image_url>"
```

**文件名规则**：
- 使用描述性英文名：`joe_hisaishi_concert.jpg`，而不是 `image1.jpg`
- 小写，下划线代替空格
- 包含主题和上下文：`spirited_away_poster.jpg`, `tokyo_concert_2023.jpg`

#### 3.4 完整分辨率 URL 模式
常见来源的完整分辨率 URL 提取方法：
- **维基媒体**：缩略图 URL 如 `.../thumb/a/ab/File.jpg/250px-File.jpg` → 移除 `/thumb/` 和 `/250px-File.jpg`，得到 `.../a/ab/File.jpg`
- **吉卜力官网**：`www.ghibli.jp/gallery/thumb-xxx.png` → `www.ghibli.jp/gallery/xxx.jpg`

### Step 4: 输出摘要
完成后输出简要总结（格式见原文件）。

> 此后，用户或主流水线可以将这些材料作为 PPT 生成的输入（通过 `project_manager.py import-sources` 或直接读取）。

### 注意事项
- 该工作流**仅限内容搜集**，不创建 PPT 项目、生成 SVG 或输出设计规范。
- Markdown 文档应**PPT 就绪**：结构良好、事实准确、章节清晰，能自然映射到幻灯片。
- 始终在 Markdown 中包含**来源**部分，用于归属和可验证性。
- 对于知名主题（名人、主要技术），2-3 轮 WebSearch + WebFetch 通常足够；避免过度研究。
- 对于小众主题，可能需要更广泛的搜索 —— 自行判断。

## 如何使用 `topic-research` 工作流：完整指南

### 适用场景
- 用户只给出了主题名称（如“人工智能历史”），没有任何源文件。
- 用户给出了简短描述（如“介绍我们的新产品 XXX”），但没有现成的文档。
- 你希望快速生成一份结构化的内容草稿，作为后续 PPT 生成的素材。

### 准备工作
- 无需任何素材。AI 会自行搜索网络。
- 建议用户明确主题和范围，以便 AI 聚焦研究。

### 完整操作步骤（与 AI 对话）

**场景示例**：用户想要制作关于“久石让”的 PPT。

**步骤 1：触发工作流**
```
你：请使用 topic-research 工作流，帮我研究“久石让”这个主题，准备制作 PPT。
```

**步骤 2：AI 确认信息（如果必要）**
如果用户信息不足，AI 会询问：
- 范围（生平？作品？与宫崎骏的合作？）
- 深度（概述还是深入分析？）
- 语言（中文/英文？）

用户可简单回答：“涵盖生平、主要作品、与宫崎骏的合作，深度一般，中文。”

**步骤 3：AI 进行研究**
AI 执行：
- WebSearch “久石让 生平” “久石让 主要作品” “久石让 宫崎骏” 等。
- WebFetch 维基百科页面、吉卜力官网等。
- 组织内容，生成 Markdown 文档。

**步骤 4：AI 收集图片**
AI 从维基共享资源、官方网站等下载图片：
- 久石让肖像照
- 音乐会现场照片
- 电影海报（《龙猫》、《千与千寻》等）
- 专辑封面

图片保存到 `projects/joe_hisaishi/`，文件名如 `joe_hisaishi_portrait.jpg`, `spirited_away_poster.jpg`。

**步骤 5：AI 输出摘要**
AI 输出类似：
```markdown
## Topic Research Complete

**Topic**: joe_hisaishi
**Document**: `projects/joe_hisaishi.md` — 8 sections, approximately 2400 words
**Images**: `projects/joe_hisaishi/` — 9 images collected

| Filename | Source | Description |
|----------|--------|-------------|
| joe_hisaishi_portrait.jpg | Wikimedia Commons | Portrait of Joe Hisaishi |
| spirited_away_poster.jpg | Wikimedia Commons | Spirited Away movie poster |
| ...
```

### 注意事项

- **输出位置**：必须放在 `projects/` 目录下，不能放在其他地方。如果 `projects/` 不存在，AI 应先创建。
- **图片版权**：AI 应优先使用公共领域或 CC 许可的图片。避免下载有明确版权的图片。
- **文件名一致性**：Markdown 文件名和图片文件夹名必须完全相同（如 `joe_hisaishi.md` 和 `joe_hisaishi/`）。
- **来源引用**：Markdown 文档末尾必须包含来源列表，以便用户核实和归属。
- **后续使用**：研究完成后，用户可以：
  - 直接编辑 Markdown 文件补充内容。
  - 使用 `project_manager.py import-sources` 将 Markdown 导入到新项目，然后继续 PPT 生成流水线。

## 总结：两个工作流的定位与关系

| 工作流 | 目的 | 输出 | 与主流水线关系 |
|--------|------|------|----------------|
| `create-template` | 创建全局布局模板 | `templates/layouts/<id>/` 下的 SVG + design_spec.md + 索引更新 | 为主流水线的 Step 3（模板选择）提供新选项 |
| `topic-research` | 从零研究主题，生成内容 | `projects/<topic>.md` + 图片文件夹 | 为主流水线的 Step 1（源内容处理）提供源材料 |

它们都是**预处理**工作流，不直接生成 PPT，但为后续的 PPT 生成提供了必要的基础设施（模板或内容）。用户可以根据需要独立调用它们，然后再进入主流水线。
