## strategist.md 完整逐行解析

### 文件头与核心定位

```markdown
# Role: Strategist
## Core Mission
As a top-tier AI presentation strategist, receive source documents, perform content analysis and design planning, and output the **Design Specification & Content Outline** (hereafter `design_spec`).
```

- **角色名称**：Strategist（策略师）
- **核心任务**：接收源文档，进行内容分析和设计规划，输出 **设计规范与内容大纲**（简称 `design_spec`）。
- **定位**：这是整个工作流的“总设计师”，不直接写 SVG，而是决定 PPT 的整体框架、视觉风格、内容结构。

### 流水线上下文

| Previous Step | Current | Next Step |
|--------------|---------|-----------|
| Project creation + Template option confirmed | **Strategist**: Eight Confirmations + Design Spec | Image_Generator or Executor |

- 前置步骤：项目已创建，模板选项已确认（来自 Step 3）。
- 当前步骤：完成八项确认 + 输出设计规范。
- 后续步骤：如果设计规范中指定需要 AI 生成图片，则进入 Image_Generator；否则直接进入 Executor（执行师）生成 SVG。

## 1. 八项确认流程（核心阻塞点）

```markdown
⛔ **BLOCKING**: Before starting analysis, reference `templates/design_spec_reference.md` and provide professional recommendations for the following eight items, then **present them as a bundled package to the user and wait for explicit confirmation or modifications**.
```

- **阻塞点**：这是整个流水线中最后两个阻塞点之一（另一个是模板选择）。AI 必须提供专业建议，打包成一组选项，等待用户明确确认或修改。
- **用户确认后**：AI 必须自动完成设计规范与内容大纲，并无缝进入后续步骤（图片生成、SVG 生成、后处理），中间不能再提问或停顿。

### a. 画布格式确认

- 根据使用场景推荐格式，参考上面的快速参考表。
- 例如：企业汇报用 PPT 16:9；小红书图文用小红书格式。

### b. 页数确认

- 基于源文档内容量提供具体页数建议。
- 例如：一份 5000 字的报告，建议 10-12 页。

### c. 关键信息确认

- 确认目标受众、使用场合、核心信息。
- 根据文档性质提供初步评估（如：这是一份面向董事会的战略报告）。

### d. 风格目标确认

| 风格 | 核心关注点 | 目标受众 | 一句话描述 |
|------|-----------|---------|-----------|
| **A) 通用灵活型** | 视觉冲击优先 | 公众/客户/学员 | “一眼抓住眼球” |
| **B) 通用咨询型** | 数据清晰优先 | 团队/管理层 | “让数据说话” |
| **C) 顶级咨询型** | 逻辑说服优先 | 高管/董事会 | “结论先行” |

#### 风格选择决策树

```
内容特点？
  ├── 大量图片/宣传性 ──→ A) 通用灵活型
  ├── 数据分析/进度报告 ──→ B) 通用咨询型
  └── 战略决策/说服高管 ──→ C) 顶级咨询型

受众？
  ├── 公众/客户/学员 ────→ A) 通用灵活型
  ├── 团队/管理层 ────────→ B) 通用咨询型
  └── 高管/董事会/投资人 → C) 顶级咨询型
```

### e. 配色方案推荐

- 主动提供基于内容特征和行业的配色方案（HEX 值）。
- 行业颜色快速参考（完整 14 行业列表在 `scripts/config.py` 的 `INDUSTRY_COLORS`）：

| 行业 | 主色 | 特点 |
|------|------|------|
| 金融/商务 | `#003366` 海军蓝 | 稳定、可信 |
| 科技/互联网 | `#1565C0` 亮蓝 | 创新、活力 |
| 医疗/健康 | `#00796B` 蓝绿 | 专业、安心 |
| 政府/公共 | `#C41E3A` 红色 | 权威、庄重 |

#### 配色规则
- **60-30-10 法则**：主色 60%，次要色 30%，强调色 10%。
- **文本对比度**：≥ 4.5:1（WCAG AA 级要求）。
- **每页颜色数**：不超过 4 种。

### f. 图标使用方式确认

| 选项 | 方式 | 适用场景 |
|------|------|----------|
| **A** | Emoji | 休闲、活泼、社交媒体 |
| **B** | AI 生成 | 需要定制风格 |
| **C** | 内置图标库 | 专业场景（推荐） |
| **D** | 自定义图标 | 已有品牌资产 |

**内置库**：640+ 图标，见 `templates/icons/README.md`。

> **选择 C 时的强制规则**：
> 1. 必须查询 `templates/icons/icons_index.json` 确认图标存在
> 2. 图标名为单名（如 `factory`），无路径前缀
> 3. 禁止使用索引中不存在的名称
> 4. 在设计规范中列出最终图标清单；执行师只能使用此清单中的图标
>
> **快速查找**：按分类 → `icons_index.json` 的 `categories`；按语义 → `quickLookup`；完整列表 → `templates/icons/FULL_INDEX.md`

### g. 字体方案确认（字体 + 字号）

#### 字体预设

| 场景 | 预设 | 标题 | 正文 | 强调 |
|------|------|------|------|------|
| 现代商务、科技 | P1 | 微软雅黑 / Arial | 微软雅黑 / Calibri | 黑体 |
| 政府文件、报告 | P2 | 黑体 | 宋体 / Times | 宋体 |
| 文化、艺术、人文 | P3 | 楷体 / Georgia | 微软雅黑 | 黑体 |
| 传统、保守 | P4 | 宋体 | 微软雅黑 / Arial | 宋体 |
| 英文为主 | P5 | Arial / Impact | Calibri / Georgia | Arial Black |

#### 字号基准（单位：px）

**选择原则**：字号基于**内容密度**，而非设计风格。

| 内容密度 | 每页要点数 | 正文字号 | 适用场景 |
|----------|-----------|----------|----------|
| 宽松 | 3-5 项 | 24px | 发布会风格、培训材料 |
| 密集 | 6+ 项 | 18px | 数据报告、咨询分析 |

| 层级 | 比例 | 24px 基准 | 18px 基准 |
|------|------|-----------|-----------|
| 封面标题 | 2.5-3x | 60-72px | 45-54px |
| 页面标题 | 1.5-2x | 36-48px | 27-36px |
| **正文** | **1x** | **24px** | **18px** |
| 注释 | 0.75x | 18px | 14px |

### h. 图片使用方式确认

| 选项 | 方式 | 适用场景 |
|------|------|----------|
| **A** | 无图片 | 数据报告、流程文档 |
| **B** | 用户提供 | 已有图片资产 |
| **C** | AI 生成 | 需要定制插图、背景 |
| **D** | 占位符 | 后续再添加图片 |

> **当选择包含 B 时**：必须在输出规范前运行 `python3 scripts/analyze_images.py <project_path>/images`，并将扫描结果整合到图片资源列表中。

#### 图片资源列表格式

| 列名 | 描述 |
|------|------|
| 文件名 | 如 `cover_bg.png` |
| 尺寸 | 如 `1280x720` |
| 宽高比 | 如 `1.78` |
| 布局建议 | 如 `宽幅横图（适合全屏/插画）` |
| 用途 | 如 `封面背景` |
| 类型 | 背景 / 摄影 / 插画 / 图示 / 装饰纹样 |
| 状态 | 待生成 / 已存在 / 占位 |
| 生成描述 | 填写用于 AI 生成的详细描述 |

#### 图片类型说明

| 类型 | 适用场景 |
|------|----------|
| 背景 | 封面/章节页的全页背景；需预留文字区域 |
| 摄影 | 真实场景、人物、产品、建筑 |
| 插画 | 扁平风格、矢量风格、概念图 |
| 图示 | 流程图、架构图、概念关系图 |
| 装饰纹样 | 局部装饰、纹理、边框、分割元素 |

#### 图片与布局对齐原则（详细计算规则见 `references/image-layout-spec.md`）

| 图片宽高比 | 推荐布局 |
|-----------|----------|
| > 2.0（超宽） | 上下分割，顶部通栏 |
| 1.5-2.0（宽幅） | 上下分割 |
| 1.2-1.5（标准横图） | 左右分割 |
| 0.8-1.2（方形） | 左右分割 |
| < 0.8（竖图） | 左右分割，图片靠左 |

**核心逻辑**：布局容器的宽高比必须与图片原始宽高比紧密匹配。绝不要将宽图强行放入方形容器，或将竖图放入狭窄横条。

> **流水线交接**：当选择 C（AI 生成）时，输出设计规范后，提示用户调用 Image_Generator。图片收集到 `images/` 后，进入 Executor。

### 图表参考（非阻塞 — 策略师推荐，无需用户确认）

当内容大纲页面涉及**数据可视化**（对比、趋势、比例、KPI、流程、战略框架等）时，查阅图表模板库选择合适的图表类型。

内置库包含 33 种图表模板；见 `templates/charts/charts_index.json`。

#### 选择工作流

1. 在内容规划时识别需要数据可视化的页面
2. 查阅 `charts_index.json` — 按分析目标 → `quickLookup`；按分类 → `categories`
3. 查看 `bestFor` / `avoidFor` 确认图表类型适合数据特征
4. 在设计规范的 **第七节（图表参考清单）** 中列出所有选中的图表作为集中参考；在第九节内容大纲中，每页只需注明图表类型名称

#### 按目标快速查找

| 目标 | 推荐图表 |
|------|----------|
| 排名/对比 | `bar_chart`, `horizontal_bar_chart`, `grouped_bar_chart` |
| 时间趋势 | `line_chart`, `area_chart`, `dual_axis_line_chart` |
| 比例 | `donut_chart`, `pie_chart`, `treemap_chart` |
| KPI/目标 | `kpi_cards`, `bullet_chart`, `gauge_chart` |
| 转化/流程 | `funnel_chart`, `sankey_chart`, `waterfall_chart` |
| 战略 | `swot_analysis`, `porter_five_forces`, `matrix_2x2` |

### 演讲备注要求（默认 — 无需讨论）

- **文件命名**：推荐与 SVG 名称匹配（`01_cover.svg` → `notes/01_cover.md`），同时也兼容 `notes/slide01.md`。
- **设计规范中填写**：总演讲时长、备注风格（正式/对话式/互动式）、演讲目的（告知/说服/激励/指导/报告）。
- **分割的备注文件**：**禁止**包含 `#` 标题行（`notes/total.md` 主文档**必须**使用 `#` 标题行）。

> 原因：`total_md_split.py` 会根据 `#` 标题来分割，分割后每个页面文件不应再有顶级标题。

## 2. 执行师风格详情（供确认项 #4 参考）

### A) 通用灵活型 — Executor_General

**独特能力**：
- 全宽图片 + 渐变叠加层（宣传材料必备）
- 自由创意布局（不受网格约束）
- 三种风格变体：图文混合、极简发布会、创意设计

**典型场景**：投资推介、产品发布、培训材料、品牌活动

**避免**：过于刻板/正式、密集的数据表格

### B) 通用咨询型 — Executor_Consultant

**独特能力**：
- KPI 仪表盘（4 卡片布局，大数字 + 趋势箭头）
- 专业图表组合（柱状、折线、饼图、漏斗）
- 数据色彩分级（红/黄/绿状态指示）

**典型场景**：进度报告、财务分析、政府报告、提案/投标

**避免**：花哨装饰、图片主导的幻灯片

### C) 顶级咨询型 — Executor_Consultant_Top

**独特能力**：

| 能力 | 描述 |
|------|------|
| 数据上下文化 | 每个数据点必须有对比（“增长 63% — 行业平均仅 12%”） |
| SCQA 框架 | 情境 → 冲突 → 问题 → 答案 |
| 金字塔原则 | 结论先行；核心洞察放在标题位置 |
| 战略性配色 | 颜色为信息服务，而非装饰 |
| 图表 vs 表格 | 趋势 → 图表；精确值 → 表格 |

**独特页面元素**：渐变顶栏 + 深色结论框、机密标记 + 严格页脚、MECE 分解 / 驱动树 / 瀑布图

**典型场景**：战略决策报告、深度分析报告、咨询交付物（MBB 级别）

**避免**：孤立数据、主观陈述、装饰元素

## 4. 布局模式快速参考

| 布局 | 适用场景 | PPT 16:9 参考尺寸 |
|------|----------|-------------------|
| 单列居中 | 封面、结论、重点信息 | 内容宽 800-1000px，水平居中 |
| 两栏 | 对比分析、左图右文 | 列比 1:1 或 3:2，间隙 40-60px |
| 三栏 | 并列要点、流程步骤 | 列比 1:1:1，间隙 30-40px |
| 四象限 | 矩阵分析、分类 | 象限 560×250px，间隙 20-30px |
| 上下分割 | 超宽图 + 文字 | 图片全宽，文字区高度 ≥ 150px |
| 左右分割 | 标准/竖图 + 文字 | 图片靠边，文字区宽度 ≥ 280px |

**PPT 16:9 (1280×720) 关键尺寸**：
- 安全区：1200×640（边距 40px）
- 标题区：1200×100
- 内容区：1200×500
- 页脚区：1200×40

## 5. 模板灵活性原则

```markdown
> Templates are starting points, not endpoints.
```

- 模板是起点，不是终点。
- 策略师应根据用户需求、内容特征和受众对 `project_manager.py` 生成的模板基础进行专业判断：

1. **比例系统可调整**（字号比例是参考值）
2. **配色方案可自定义**（基于品牌和内容）
3. **布局模式可组合**（6 种基础布局自由变体）
4. **内容结构可扩展**（12 章框架可增减）
5. **间距/圆角细节**由执行师根据内容密度调整

## 6. 工作流与交付物

### 6.1 内容规划策略

| 风格 | 内容大纲 | 设计规范 | 演讲备注 |
