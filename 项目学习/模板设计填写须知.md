## 一、审查结论：这份提示词是否合适？

**非常合适。** 这是一份专业、完整、可直接交付给设计师（或 AI 设计 Agent）的需求文档。它具备以下优点：

| 维度 | 评价 |
|------|------|
| **结构清晰** | 从基本信息、设计规范到输出文件要求，逐层递进 |
| **可执行性强** | 明确要求生成 `design_spec.md` + 6 个 SVG 文件 + 注册 JSON |
| **技术约束完整** | 列出了 SVG 必须遵守的规则（viewBox、禁用元素等），避免生成不兼容代码 |
| **示例充足** | 提供 `google_style` 等参考，降低理解成本 |
| **占位符规范** | 定义了常用占位符，确保与 PPT Master 工作流对接 |

### 需要⚠️注意的细节（可优化）

1. **章节页风格描述**：提示词第 2.4 节中“章节页风格”选项包含 `大数字 + 标题`，但未明确大数字是**前景**还是**背景半透明**。建议补充说明，避免歧义。
2. **Logo 放置位置**：提示词仅说“在封面和内容页页眉适当位置加入”，但实际可能只需要放在结尾页。建议允许用户指定具体页面和位置（如“右上角”或“底部居中”）。
3. **公众号等自定义占位符**：若模板需要显示公众号名称、二维码等，应在占位符规范中明确增加 `{{WECHAT_PUBLIC_NAME}}` 等字段。
4. **内容页的页脚内容**：目前默认包含 `{{SOURCE}}` 和 `{{PAGE_NUM}}`。若需要增加公司名或日期，应提前说明。

**结论**：直接交给设计师使用完全可行，设计师会按照提示词逐项填写并输出模板文件。

## 二、设计师（或 AI）应该如何填写这份提示词？

设计师拿到这份提示词后，需要完成两件事：

1. **与用户沟通**，获取 `[方括号]` 中缺失的个性化信息（颜色、字体、布局偏好等）。
2. **生成最终的 `design_spec.md` 和 SVG 文件**。

### 设计师需要向用户获取的信息清单

以下表格列出了提示词中每个 `[方括号]` 对应的**具体问题**，设计师应逐一询问用户：

| 章节 | 字段 | 需要问用户的问题 |
|------|------|------------------|
| 1 | 模板 ID | 你希望用什么英文标识？（小写+下划线，如 `my_brand`） |
| 1 | 模板显示名称 | 展示给用户的名称，如“XX公司科技风” |
| 1 | 分类 | 选择：`brand`/`general`/`scenario`/`government`/`special` |
| 1 | 适用场景 | 例如“技术文章配图、年度报告、产品发布” |
| 1 | 调性摘要 | 用 3-5 个词描述：如“专业、数据驱动、清晰” |
| 1 | 主题模式 | 浅色 / 深色 / 混合 |
| 1 | 快速查找标签 | 可选，如 `tech, data, wechat` |
| 2.1 | 品牌色 | 提供主色、辅色、强调色等的 **HEX 值**（至少 5 个） |
| 2.2 | 字体方案 | 字体栈（推荐系统 UI）、封面标题字号、页面标题字号、正文字号 |
| 2.3 | 品牌资产 | 提供 logo 文件（PNG/SVG）、背景纹理（若有）、参考设计图 |
| 2.4 | 封面风格 | 全屏背景 / 居中卡片 / 左对齐大标题 / 带斜纹装饰 |
| 2.4 | 章节页风格 | 大数字+标题 / 全图背景+标题 / 极简线框（**明确大数字是前景还是背景**） |
| 2.4 | 内容页页眉 | 是否显示标题下划线？是否显示 Logo？页眉高度（px） |
| 2.4 | 页脚内容 | 页码 / 公司名 / 日期 / 保密标记 / 公众号名称（具体列出） |
| 2.4 | 圆角大小 | 卡片圆角：8px / 12px / 16px |
| 2.4 | 阴影效果 | 是否需要阴影？柔和阴影还是扁平？ |
| 2.5 | 额外设计说明 | 任何特殊要求，如“主色仅用于标题和关键数据点” |

### 设计师填写示例（以 `tech_data_vis` 为例）

填充后的提示词第 2 节应类似：

```markdown
### 2.1 品牌色
- 主色：`#1F4E7A`（科技深蓝）
- 辅色：`#2E7D32`（生态森林绿）
- 强调色：`#6A1B9A`（突破性紫色）
- 成功/正向色：`#2E7D32`
- 警告/负向色：`#EF6C00`
- 背景色：`#FFFFFF`
- 正文文字色：`#546E7A`
- 次要文字色：`#90A4AE`
```

## 三、如果你作为用户（甲方），应该如何与设计同事协作？

### 最佳流程：你填写 → 设计师执行

**你不需要自己会设计**，但你需要**明确自己的需求和偏好**。以下是建议的沟通步骤：

#### Step 1：整理“设计灵感板”
- 收集 3-5 张你喜欢的 PPT 风格截图（或公众号文章配图）。
- 标注你喜欢的具体元素：配色、字体、卡片圆角、阴影、图标风格等。

#### Step 2：回答设计师的 10 个核心问题（简化版）

你可以直接回答以下问题，无需了解技术细节：

1. **这个 PPT 主要给谁看？**（如：公众号读者、投资人、内部团队）
2. **用一个词形容想要的风格？**（如：专业、科技、温暖、权威）
3. **主色调是什么？**（可提供公司 logo 的颜色，或喜欢的颜色参考）
4. **需要深色还是浅色背景？**（通常浅色更适合技术文章）
5. **封面想要简洁还是丰富？**（居中大标题？带装饰？）
6. **章节页需要大数字分隔吗？**（需要，且数字要显眼）
7. **每页底部放什么？**（页码、数据来源、公众号名称）
8. **是否有固定 logo？**（提供文件，告知想放的位置：封面/内容页/结尾页）
9. **是否有特殊文字需要每页出现？**（如“海纳百川集思录”）
10. **是否有参考模板？**（可提供你之前看到的任何样例）

#### Step 3：将上述答案填入提示词的 `[方括号]` 中

你不需要一次性填完所有技术细节（如 HEX 值）。可以先用文字描述颜色，设计师会帮你转换成 HEX。例如：

> 主色：深蓝色，类似 AWS 的 #1F4E7A；辅色：森林绿 #2E7D32。

#### Step 4：把填充后的提示词 + 素材（logo、参考图）发给设计师

设计师将严格按照提示词生成最终的 SVG 和 `design_spec.md`。

## 四、如果设计师（或 AI）需要根据“设计思路”自行发挥怎么办？

有些用户无法提供精确的 HEX 值或字号，只能描述“我想要科技感、数据可视化风格”。此时，设计师需要**主动补充缺失的信息**，基于行业通用标准进行合理假设。

### 设计师需要具备的“默认决策能力”

| 缺失信息 | 默认采用的方案 |
|----------|----------------|
| 颜色 | 使用主流的科技蓝 (#1F4E7A) + 青色 (#00838F) + 紫 (#6A1B9A) |
| 字体 | 系统 UI 栈，正文字号 20px，标题 40px |
| 圆角 | 12px |
| 阴影 | 轻微阴影（filter 实现） |
| 章节页 | 前景大数字 + 标题（参考 Google 风格） |
| 封面 | 居中卡片设计 |
| 页脚 | 页码 + 数据来源 |

**但设计师必须在输出文件中明确记录这些决策**（写在 `design_spec.md` 的配色方案、字体方案中），以便用户审查和修改。
