## PPT Master 服务 Docker 化与集成方案

根据你现有的服务器架构（主服务 + 独立沙箱服务 + Cloudflare Tunnel），PPT Master 应当作为**另一个独立的 Docker 服务**部署，通过 Cloudflare Tunnel 暴露一个专用域名（如 `ppt.10110531.xyz`）供前端调用，或者由主服务的 `tool_registry` 通过 HTTP 内部调用它。

### 一、整体架构设计

```
前端 (AI 模型)
   │
   ├── 多轮对话 + 工具调用
   │
   ▼
主服务 (tools.10110531.xyz:8827)
   │
   ├── 工具注册表 (tool_registry)
   │   ├── tavily_search
   │   ├── firecrawl
   │   ├── python_sandbox (HTTP 调用独立容器)
   │   └── ppt_master (HTTP 调用独立容器)  ← 新增
   │
   └── Cloudflare Tunnel
        ├── tools.10110531.xyz → 主服务
        ├── pythonsandbox.10110531.xyz → 沙箱容器
        └── ppt.10110531.xyz → PPT Master 容器 (新增)
```

**选择方案**：新增独立域名 `ppt.10110531.xyz`，PPT Master 容器直接对外提供服务，主服务通过 HTTP 调用它。这样做的好处：
- 环境完全隔离，不影响主服务稳定性。
- 可以独立扩展、更新。
- 前端也可以直接调用（如果模型有工具调用权限）。

    完整流程：初始化项目 → 导入 Markdown → 生成 SVG（需外部 AI） → 后处理 → 返回 PPTX
    """
    proj_id = uuid.uuid4().hex[:8]
    proj_dir = Path(f"/tmp/ppt_master_{proj_id}")

        # 1. 初始化项目
        subprocess.run([
            "python3", "skills/ppt-master/scripts/project_manager.py",
            "init", proj_id, "--format", req.canvas_format, "--dir", str(proj_dir.parent)
        ], check=True, capture_output=True)

        # 2. 导入 Markdown
        sources_dir = proj_dir / "sources"
        sources_dir.mkdir(exist_ok=True)
        md_file = sources_dir / "content.md"
        md_file.write_text(req.markdown, encoding="utf-8")

                    shutil.copy(f, target_tmpl / f.name)
                spec_file = template_dir / "design_spec.md"
                if spec_file.exists():
                    shutil.copy(spec_file, target_tmpl / "design_spec.md")

        # 4. 生成 SVG（需要调用大模型 API）

### 三、Cloudflare Tunnel 配置

你需要为 PPT Master 服务分配一个子域名，比如 `ppt.10110531.xyz`。

**步骤**：
1. 编辑 Cloudflare Tunnel 配置文件 `/home/ren/.cloudflared/config.yml`，在 `ingress:` 部分添加新规则：

```yaml
ingress:
  - hostname: tools.10110531.xyz
    service: http://localhost:8827
  - hostname: pythonsandbox.10110531.xyz
    service: http://localhost:8828
  - hostname: ppt.10110531.xyz          # 新增
    service: http://localhost:8829      # 指向 Docker 映射的端口
  - service: http_status:404
```

2. 重启 Cloudflare Tunnel：
   ```bash
   sudo systemctl restart cloudflared
   ```

3. 添加 DNS 记录：
   ```bash
   cloudflared tunnel route dns my-private-server ppt.10110531.xyz
   ```

import httpx
from pydantic import BaseModel
from typing import Optional

class PPTMasterInput(BaseModel):
    markdown: str
    template: str = "google_style"
    canvas_format: str = "ppt169"
    design_params: Optional[dict] = None

class PPTMasterTool:
    name = "ppt_master"
    description = "Generate a PPTX file from Markdown content using PPT Master. Returns base64 encoded PPTX."
    input_schema = PPTMasterInput

    async def execute(self, params: PPTMasterInput, session_id: str = "temp") -> dict:
        async with httpx.AsyncClient(timeout=180.0) as client:
            resp = await client.post(
                "http://localhost:8829/generate",   # 容器内部端口，也可用域名
                json=params.dict()
            )
            if resp.status_code == 200:
                data = resp.json()
                if data.get("success"):
                    # 可以将 PPTX 保存到会话工作区（如果沙箱需要）
                    pptx_bytes = base64.b64decode(data["pptx_base64"])
                    pptx_path = f"/srv/sandbox_workspaces/{session_id}/output.pptx"
                    # 异步写入文件
                    # ...
                    return {"success": True, "pptx_base64": data["pptx_base64"]}
                else:
                    return {"success": False, "error": data.get("message")}
            else:
                return {"success": False, "error": f"HTTP {resp.status_code}"}

### 五、工具粒度评估

**建议采用单一工具** `ppt_master`，因为：
- PPT 生成是一个完整、原子性的任务，中间步骤（初始化、导入、SVG 生成、后处理）通常不需要用户干预。
- 多轮对话中，用户只需要提供 Markdown 和可选参数，等待最终 PPTX。
- 拆分多个工具会增加前端调用复杂度（需要维护状态、步骤顺序），且容易出错。

**如果需要调试或分步执行**，可以在工具内部增加 `steps` 参数，支持 `init`, `import`, `generate_svg`, `postprocess` 等子步骤，并返回中间产物（如 SVG 代码）。但作为首次集成，建议先实现完整流程。

**AI 生成 SVG 的集成**：这是最大的挑战。PPT Master 原本需要 AI 编辑器（Claude Code）通过多轮对话生成 SVG。要完全自动化，你需要在 `_call_ai_to_generate_svg` 中：
- 读取设计规范（从模板的 `design_spec.md` 获取）。
- 构造系统提示词（可复用 `references/executor-base.md` 等）。
- 调用大模型 API（Claude 3.5 Sonnet 或 GPT-4），要求模型输出多页 SVG 代码（每页用 `---` 分隔）。
- 解析模型输出，验证 SVG 是否符合规范（可使用 `svg_quality_checker.py`），必要时重试。

**简化方案**：如果你暂时无法实现 AI 自动生成 SVG，可以先用一个“占位”版本：只做模板填充（将 Markdown 内容塞进固定布局），不依赖 AI。这样至少可以生成一个基本的 PPTX。之后逐步增强。

### 八、注意事项

1. **大模型 API 成本**：自动生成 SVG 会消耗大量 token，建议缓存常见页面的 SVG 或使用更便宜的模型。
2. **并发与资源限制**：PPT 生成消耗 CPU/内存，Docker 资源限制为 2C4G，可根据需要调整。
3. **超时**：PPT 生成可能需要 30 秒以上，需设置较长的 HTTP 超时（建议 180 秒）。
4. **环境变量**：API keys 可以通过 `.env` 文件或 Docker 环境变量传递。
5. **持久化**：临时项目目录放在 `/tmp` 会自动清理，无需持久化。
6. **日志**：建议在 `api.py` 中添加日志，便于调试。

通过以上方案，你可以将 PPT Master 无缝集成到现有的工具服务器生态中，并利用 Cloudflare Tunnel 安全对外提供服务。
