## 1. 模板遵循规则

如果项目 `templates/` 目录中存在模板文件，则必须遵循模板结构：

| 页面类型 | 对应模板 | 遵循规则 |
|----------|----------|----------|
| 封面 | `01_cover.svg` | 继承背景、装饰元素、布局结构；替换占位内容 |
| 章节页 | `02_chapter.svg` | 继承编号样式、标题位置、装饰元素 |
| 内容页 | `03_content.svg` | 继承页眉/页脚样式；**内容区可自由布局** |
| 结尾页 | `04_ending.svg` | 继承背景、致谢信息位置、联系方式布局 |
| 目录页 | `02_toc.svg` | **可选**：继承目录标题、列表样式 |

> 注意：`02_chapter.svg` 和 `02_toc.svg` 都使用 `02_` 前缀，但功能不同。模板系统通过文件名区分。

### 页面-模板映射声明（必须输出）

生成每一页之前，必须明确输出使用了哪个模板（或“自由设计”）：

```markdown
📝 **Template mapping**: `templates/01_cover.svg` (or "None (free design)")
🎯 **Adherence rules / layout strategy**: [specific description]
```

- **内容页**：模板只定义页眉和页脚，内容区由执行师自由布局
- **无模板**：完全按照设计规范与内容大纲生成

## 2. 设计参数确认（强制步骤）

> 在生成第一个 SVG 页面之前，**必须审查设计规范与内容大纲中的关键设计参数**，确保后续所有生成严格遵循规范。

必须输出确认内容包括：画布尺寸、正文字号、配色方案（主色/次色/强调色的 HEX 值）、字体方案。

**为什么必须做这一步？** 防止“规范说一套，执行做一套”的脱节。

## 3. 执行准则

### 邻近原则
- 将相关元素靠近放置，形成视觉组；增加不相关组之间的间距，强化逻辑结构

### 绝对遵循规范
- 严格遵守规范中的颜色、布局、画布格式、字体参数

### 遵循模板结构
- 如果存在模板，继承模板的视觉框架

### 主代理所有权
- SVG 生成必须由当前主代理执行，不能委托给子代理，因为每一页依赖于共享的上游上下文和跨页视觉连续性

### 生成节奏
- 先锁定全局设计上下文，然后在同一连续上下文中一页一页顺序生成；不允许分组批量生成（如一次 5 页）

### 分阶段批量生成（推荐）
1. **视觉构建阶段**：按顺序连续生成所有 SVG 页面，确保设计风格和布局坐标的高度一致性（视觉一致性）
2. **逻辑构建阶段**：所有 SVG 定稿后，批量生成演讲备注，确保叙事连贯性（叙事连续性）

### 技术规范
- 参见 `shared-standards.md` 了解 SVG 技术约束和 PPT 兼容规则

### 视觉深度
- 使用过滤阴影、发光效果、渐变填充、虚线描边和渐变叠加层（来自 shared-standards.md）来创造层次深度——没有层次或强调的扁平页面看起来不完整

### SVG 文件命名约定

格式：`<数字>_<页面名称>.svg`

- **中文内容** → 中文命名：`01_封面.svg`, `02_目录.svg`, `03_核心优势.svg`
- **英文内容** → 英文命名：`01_cover.svg`, `02_agenda.svg`, `03_key_benefits.svg`
- **数字规则**：两位数，从 01 开始
- **页面名称**：简洁且有描述性，与设计规范中的页面标题匹配

## 8. 演讲备注生成框架

### 任务 1. 生成完整的演讲备注文档

**在所有 SVG 页面生成并定稿后**，进入“逻辑构建阶段”，在 `notes/total.md` 中生成完整的演讲备注文档。

**为什么不在页面生成时逐页生成？** 批量撰写备注可以像脚本一样规划过渡，确保连贯的演讲逻辑。

**格式**：
- 每页以 `# <数字>_<页面标题>` 开头
- 页面之间用 `---` 分隔
- 每页包括：讲稿文本（2-5 句）、`要点：① ② ③`、`时长：X 分钟`
- 除第一页外，每页文本以 `[过渡]` 短语开头

### 基本舞台指示标记（所有风格通用）

| 标记 | 用途 |
|------|------|
| `[Pause]` | 关键内容后的空白，让听众吸收 |
| `[Transition]` | 每页文本开头的独立段落，衔接上一页 |

> 每种风格可能扩展其他标记（`[互动]`/`[数据]`/`[观察]`/`[对标]` 等），参见 `executor-{style}.md`。

### 语言一致性规则

演讲备注中的所有结构标签和舞台指示标记**必须与演示内容语言匹配**。当演示内容非英语时，本地化每个标签 — 不要将英语标签与非英语内容混用。

| English | 中文 | 日本語 | 한국어 |
|---------|------|--------|--------|
| `[Transition]` | `[过渡]` | `[つなぎ]` | `[전환]` |
| `[Pause]` | `[停顿]` | `[間]` | `[멈춤]` |
| `[Interactive]` | `[互动]` | `[問いかけ]` | `[상호작용]` |
| `[Data]` | `[数据]` | `[データ]` | `[데이터]` |
| `[Scan Room]` | `[观察]` | `[観察]` | `[관찰]` |
| `[Benchmark]` | `[对标]` | `[ベンチマーク]` | `[벤치마크]` |
| `Key points:` | `要点：` | `要点：` | `핵심 포인트:` |
| `Duration:` | `时长：` | `所要時間：` | `소요 시간:` |
| `Flex:` | `弹性：` | `調整：` | `조정:` |

> 对于上面未列出的语言，将每个标签翻译成该语言的相应自然术语。

**要求**：
- 备注应对话自然、流畅
- 突出每页的核心信息和演讲要点
- 用户可以在 `notes/` 目录中手动编辑和覆盖

### 任务 2. 分割成每页备注文件

自动将 `notes/total.md` 分割成 `notes/` 目录中的单个演讲备注文件。

**文件命名约定**：
- **推荐**：匹配 SVG 名称（例如 `01_cover.svg` → `notes/01_cover.md`）
- **兼容**：也支持 `slide01.md` 格式（向后兼容）

## 角色定义

---

## 咨询特有的数据可视化技术

### 1. KPI 仪表板设计

KPI 卡片是咨询报告中最常见的元素。标准布局（1280×720）：

```
4 卡片布局：每张卡片 280×180，间隙 30
  卡片 1: x=45,  y=160
  卡片 2: x=355, y=160
  卡片 3: x=665, y=160
  卡片 4: x=975, y=160
```

**卡片内部结构**（从上到下）：

| 区域 | 内容 | 字号 | 样式 |
|------|------|------|------|
| 图标行 | data-icon 图标 | 32×32 | 主题色 |
| 指标名称 | "月活跃用户" | 14px | 灰色 #64748B |
| 核心数字 | "1.2M" | 36-42px | 粗体，深色 |
| 趋势注释 | "较上月增长 +12.3%" | 12px | 绿色=上升 / 红色=下降 |

**趋势箭头惯例**：
- 上升：`arrow-trend-up` 图标 + 绿色文字
- 下降：`arrow-trend-down` 图标 + 红色文字
- 持平：水平线图标 + 灰色文字

### 2. 图表颜色惯例

咨询风格图表使用**单色深度渐变**而非彩虹色：

```
主系列：   主题色 100% 不透明度
对比系列： 主题色 60% 不透明度
基线：     #94A3B8（灰色虚线）
高亮：     强调色（仅用于关键数据点）
```

### 3. 数据标注原则

- **直接数据标签**：将数值放在柱状图顶部 — 无需图例
- **注释趋势线**：在关键拐点添加文字注释（“政策变化”、“产品发布”）
- **对比基线**：用灰色虚线标记行业平均/目标值
- **一致单位**：在图表内保持相同的数值单位和精度

### 4. 表格设计

咨询报告经常使用表格展示精确数据：

| 设计元素 | 规范 |
|----------|------|
| 表头 | 深色背景 + 白色文字，font-weight="bold" |
| 斑马条纹 | 交替行使用 `fill-opacity="0.05"` 浅色背景 |
| 数字对齐 | 数字右对齐，文本左对齐 |
| 高亮行 | 用强调色 `fill-opacity="0.1"` 标记关键行 |
| 边框 | 仅使用水平线分隔行；避免完整网格线 |

## 咨询特有的布局模式

### MECE 分解树

左侧主干，分支向右展开 — 相互独立，完全穷尽：

```
主指标 ──┬── 分支 A (45%)
        ├── 分支 B (30%)
        ├── 分支 C (20%)
        └── 分支 D (5%)
```

- 使用 `<line>` 连接主干和分支
- 每个分支有一个 `<rect>` 容器 + 百分比注释
- 总和必须 = 100%（或明确标注“其他”）

### 驱动因素树

顶层指标 → 分解因素 → 行动。适用于绩效归因分析：

```
收入增长 15%
  ├── 客单价 +8%  → 高端产品线拓展
  ├── 客户数 +5%  → 新渠道获客
  └── 复购率 +2%  → 忠诚度计划优化
```

### 左图右文（图表解读）

咨询报告核心布局：左侧图表，右侧关键洞察：

```
图表区：    x=40, y=120, w=700, h=480
洞察区：    x=780, y=120, w=460, h=480
  - 核心结论（粗体，16px）
  - 3-5 个要点（14px）
  - 数据来源（12px，灰色）
```

## 专业表达标准

### 页面标题

咨询风格页面标题应为**断言式标题**，而非描述性标题：

| 类型 | 描述性（避免） | 断言式（推荐） |
|------|----------------|----------------|
| 市场 | "市场概览" | "国内市场同比增长 23%，远超全球平均水平" |
| 竞争 | "竞争分析" | "三大竞争对手在渠道覆盖上存在明显短板" |
| 财务 | "财务数据" | "毛利率连续四季度改善，突破行业天花板" |

### 数据来源归属

每个包含数据的页面底部必须注明来源：

```xml
<text x="40" y="700" font-size="10" fill="#94A3B8">
  来源：国家统计局 2025 年报；内部团队分析
</text>
```

### 关键结论框

咨询风格内容页应在标题下方包含一个**结论框**：

```
位置：x=40, y=80, w=1200, h=50
背景：浅色主题色（fill-opacity="0.08"）
文本：14-16px，一句话总结本页核心结论
```

## 演讲备注风格

### 叙事语气

咨询风格演讲备注使用**结论驱动**方式 — 先陈述结论，再提供支持证据。专业、简洁、有说服力的语气。

### 舞台指示标记

| 标记 | 用途 | 示例 |
|------|------|------|
| `[Pause]` | 关键结论后的沉默，让听众吸收 | "这意味着我们的市场份额正在被侵蚀。[停顿]" |
| `[Data]` | 提示以对话方式口述数字 | "[数据] 85% → 超过八成客户报告了这个问题" |
| `[Transition]` | 衔接上一页，必须放在每页文本开头 | "[过渡] 基于该分析，让我们看看具体建议。" |

### 备注撰写指南

- **结论先行**：每页备注的第一句是核心结论
- **对话式数据**：30% → “大约三分之一”，85% → “超过八成”，2.5x → “两倍半”
- **证据紧随其后**：结论后提供 2-3 个支持性数据点/事实
- **专业术语**：使用“洞察”、“驱动因素”、“关键杠杆”等词汇
- **要点结构**：`要点：(1) 核心结论 (2) 支撑数据 (3) 后续步骤`

### 备注示例

```markdown
# 03_key_findings

[过渡] 基于我们的市场扫描，我们提炼出三个关键发现。

第一，增长引擎正从获客转向留存。
[数据] 新客获取成本同比上涨近 40%，而改善后的复购率贡献了超过 60% 的收入增长。[停顿]

第二，低线市场增速显著高于一二线城市。
第三，25-35 岁女性用户的 ARPU 是整体平均的 1.8 倍。

要点：(1) 增长引擎从获客转向留存 (2) 低线市场机会窗口 (3) 高价值用户画像
时长：2 分钟
```

# 三、executor-consultant-top.md —— 顶级咨询风格（MBB 级）

## 角色定义

MBB 级（麦肯锡/贝恩/BCG）顶级咨询风格 SVG 设计执行师。适用于战略规划、董事会演示、投资路演、C 级决策支持等**高端咨询**场景。核心特征：数据驱动的洞察、金字塔结构叙事、极致简洁。输出面向 C 级决策者。

---

## SCQA 框架（叙事结构）

每个 MBB 级演示都遵循 SCQA 叙事结构：

| 元素 | 目的 | 典型页数 |
|------|------|----------|
| **S - 情境** | 建立共享背景 | 封面 / 第 1-2 页 |
| **C - 冲突** | 引入问题/张力 | 第 2-3 页 |
| **Q - 问题** | 隐含或明确要解决的问题 | 过渡页 |
| **A - 答案** | 核心解决方案 | 所有正文页 |

**页面顺序**：封面体现 S+C → 执行摘要回答 Q → 章节展开 A → 结尾回到 S

**标题写法**：

| SCQA 元素 | 弱标题 | MBB 级标题 |
|-----------|--------|------------|
| S | "行业背景" | "数字化渗透率突破 60%，行业进入深水区" |
| C | "面临的挑战" | "但三大结构性矛盾制约规模化落地" |
| Q | "战略问题" | "如何 18 个月内从试点到全面铺开？" |
| A | "解决方案" | "三阶段路径：聚焦、扩张、规模化" |

## 数据上下文化（绝不孤立呈现数据）

> **黄金法则**：绝不单独显示一个数据点。每个数字都需要上下文。

| 方法 | 模式 | 视觉实现 |
|------|------|----------|
| **时间对比** | "从 X 到 Y" | 折线图 + 箭头注释变化幅度 |
| **基准对比** | "X vs 行业平均 Y" | 柱状图 + 灰色虚线基线 |
| **竞争对比** | "我方 X vs 竞品 Y" | 并排柱状图，高亮我方数据 |
| **目标差距** | "实际 X / 目标 Y" | 进度条 + 差距注释 |
| **排名** | "排名第 N / M" | 水平柱状图 + 高亮标记 |

### 数据注释三要素
每个数据可视化必须包含：
1. **数值本身**（大粗体字）
2. **对比参照**（基线/前期/竞品）
3. **意义解读**（“那又怎样？”）

```xml
<text x="160" y="280" text-anchor="middle" font-size="42" font-weight="bold" fill="#1E293B">97.3%</text>
<text x="160" y="310" text-anchor="middle" font-size="13" fill="#64748B">行业平均 82% | 竞品 A 89%</text>
<text x="160" y="335" text-anchor="middle" font-size="12" fill="#059669">领先行业 15.3 个百分点</text>
```

## 金字塔原则（结论先行）

> 高管不关心你的*过程* — 他们关心*结果*。

```
         ┌─────────────────┐
         │   核心结论       │   ← 页面标题 / 结论框
         └────────┬────────┘
      ┌───────────┼───────────┐
  ┌───┴───┐  ┌───┴───┐  ┌───┴───┐
  │ 论点1 │  │ 论点2 │  │ 论点3 │   ← 关键支撑点
  └───────┘  └───────┘  └───────┘
```

| 层级 | 位置 | 字号 |
|------|------|------|
| 核心结论 | 结论框 | 16-18px 粗体 |
| 论点 | 内容区正文 | 14-16px |
| 支撑数据 | 图表/卡片 | 12-14px |

**对比**：
- 标题“市场调研结果”（错误）→ “元宇宙需要 5-10 年才能达到规模”（正确）
- 正文“我们研究了...发现...”（错误）→ “三个论点：(1)... (2)... (3)...” （正确）

## MBB 级布局模式

### 内容页标准结构（1280×720）

```
┌──────────────────────────────────┐
│ 渐变顶栏 (0,0 → 1280,6)          │
├──────────────────────────────────┤
│ 断言式标题 (x=40, y=50, 24px)    │
├──────────────────────────────────┤
│ 结论框 (x=40, y=75, w=1200, h=45)│  ← 深色背景 + 白色文字，一句话结论
├──────────────────────────────────┤
│ 内容区 (x=40, y=140, w=1200, h=520)│ ← 图表/数据/分析
├──────────────────────────────────┤
│ 来源 | 机密 | 页码                 │  ← y=700, 10px
└──────────────────────────────────┘
```

### 战略路线图

三个阶段水平排列，`<rect rx="8">` + 标题 + 行动列表，`<polygon>` 箭头连接：

```
聚焦核心 (0-6月)  ──>  扩展能力 (6-12月)  ──>  规模化 (12-18月)
x=40,w=380              x=450,w=380            x=860,w=380
```

### 对标矩阵

水平表格；我方行用主题色高亮，其他行灰色。领先指标标记绿色，落后标记红色。使用 `<circle>` 或 `<rect>` 构建得分点。

### 瀑布图（变化归因）

起始 → 增减因素 → 结束。正向因素绿色柱，负向因素红色柱，起点/终点深色柱，累积线用虚线连接。

## 颜色的战略使用

MBB 级颜色使用极其克制 — 颜色为信息服务：

| 目的 | 方法 |
|------|------|
| **聚焦** | 目标数据用主题色，其他全部灰色 |
| **减少认知负荷** | 同一系列通过不透明度区分（`fill-opacity` 1.0/0.6/0.3） |
| **语义** | 绿色 = 正面，红色 = 负面，灰色 = 基线 |
| **品牌** | 渐变顶栏/装饰线用品牌色 |

**戒律**：主色不超过 3 种；强调色全局最多使用 2-3 处；数据系列使用同色系深浅变化，而非不同颜色；背景白色或极浅灰色。

## 图表 vs 表格选择矩阵

| 场景 | 推荐形式 | 原因 |
|------|----------|------|
| 比较 2-7 个类别 | **柱状图** | 视觉比较直观 |
| 时间趋势 | **折线图** | 时间序列清晰 |
| 精确值/大排名 | **表格** | 50 个数据点放在柱状图中会混乱 |
| 比例构成 | **环形图** | 比饼图更现代 |
| 二维定位 | **2×2 矩阵** | 战略象限分析 |
| 变化归因 | **瀑布图** | 因素分解 |

### 叙事语气

面向**高管/决策者**。金字塔结构 — 每句话都承载信息。沉稳、权威、有洞察力的语气。

## 通用特有的布局技巧

### 1. 灵活多样的布局

通用风格不受固定模板限制，可根据内容自由选择布局：

| 布局 | 使用场景 | 布局细节（1280×720） |
|------|----------|---------------------|
| 全图背景 + 文字叠加 | 封面、情感页面 | `</td> 填充画布 + 半透明叠加层 + 居中标题 |
| 左右分割（图文混合） | 功能介绍、对比 | 左 x=40,w=580 / 右 x=660,w=580 |
| 三列卡片 | 功能列表、团队介绍 | x=40,450,860 各 w=380，等高卡片 |
| 上下分割 | 时间线、流程 | 顶部区域：标题+描述 h=250 / 底部区域：图表+内容 h=420 |
| 中心放射 | 核心概念、生态系统图 | 中心元素 + 4-6 个周围节点，线条指向中心 |
| 瀑布/Z 字形 | 讲故事、案例研究 | 内容块左右交替，引导视线呈 Z 字形 |

### 2. 视觉节奏控制

- **信息密度交替**：在数据密集型页面之后跟一个“呼吸页面”（大图/引用/过渡页），防止听众疲劳
- **视觉重量平衡**：深色/大面积元素“重”，浅色/小元素“轻” — 平衡左右/上下
- **重复与变化**：章节内保持布局一致性，章节间变化以保持新鲜感

### 3. 装饰元素使用

| 元素 | 用法 | 注意事项 |
|------|------|----------|
| 渐变块 | 背景区域、标题衬底 | 使用 `<linearGradient>` / `<radialGradient>`，限制 2-3 色 |
| 圆角矩形卡片 | 内容容器、功能模块 | `rx="12"` + 浅阴影（用浅色 rect 模拟） |
| 图标点缀 | 列表项前缀、功能标记 | 使用 `data-icon` 占位符，尺寸 32-48px |
| 数字圆圈 | 步骤流程、排名列表 | `<circle>` + 居中 `<text>`，主题色填充 |
| 分割线 | 内容分隔 | `<line>` 或 `<rect height="2">`，不透明度 0.2-0.3 |

## 视觉策略

### 颜色使用

- **大胆使用主题色**：封面和章节页可使用大面积主题色背景
- **渐变增强深度**：标题栏和卡片背景可使用同色系渐变
- **对比创造焦点**：关键数字/文字使用强调色，与周围形成对比
- **颜色匹配情绪**：冷色调 → 科技感，暖色调 → 活力感，暗色调 → 庄重感

### 图片处理策略

| 场景 | 策略 | SVG 实现 |
|------|------|----------|
| 全屏背景 | 图片铺满 + 深色渐变叠加 | `preserveAspectRatio="xMidYMid slice"` + 渐变 rect |
| 竖图展示 | 靠左/右放置，保持原始比例 | 控制宽度，高度自适应 |
| 多图网格 | 网格排列，统一尺寸 | 等宽等高 `</td> 矩阵 |
| 人物照片 | 圆形裁剪效果 | `<circle>` 背景 + 方形图片叠加（后处理裁剪） |

### 字体层级

```
标题层     → 28-36px，粗体，主题色或白色
副标题层   → 20-24px，中等字重，次要色
正文层     → 16-18px，常规，深灰色
注释层     → 12-14px，浅灰色，底部对齐
```

## 演讲备注风格

### 叙事语气

通用风格演讲备注使用**对话式叙述** — 就像和听众聊天，而不是读报告。自然的语气，有节奏感，适当使用修辞手法。

### 舞台指示标记

| 标记 | 用途 | 示例 |
|------|------|------|
| `[Pause]` | 关键揭示后的沉默，让听众吸收 | "这个数字意味着什么？[停顿] 意味着每 3 个用户中就有 1 个..." |
| `[Interactive]` | 提问或引导听众参与 | "[互动] 在座有多少人用过这个功能？" |
| `[Transition]` | 衔接上一页，必须放在每页文本开头 | "[过渡] 了解了背景之后，让我们看看它是如何工作的。" |

### 备注撰写指南

- **讲故事**：每页叙述使用“情境-冲突-解决”结构
- **使用比喻**：让抽象概念变得具体（“就像给系统加了一个涡轮增压器”）
- **制造悬念**：适时提出问题，下一页回答
- **对话式数据**：30% → “近三分之一”，2.5x → “翻了一倍多”
- **要点结构**：`要点：(1) 核心信息 (2) 支撑证据 (3) 行动号召`

### 备注示例

```markdown
# 03_key_advantages

[过渡] 了解了市场格局之后，你可能会想：我们的机会在哪里？

我们的核心优势可以概括为三个词：快、准、省。
快 — 部署时间从 3 个月缩短到 2 周；[停顿]
准 — 识别准确率达 97.3%，远超行业平均的 82%；
省 — 整体成本降低近三分之一。

[互动] 如果你是决策者，这三个数字中哪个最让你印象深刻？

要点：(1) 三个差异化优势 (2) 量化数据支撑 (3) 引发思考的互动
时长：2 分钟
```
